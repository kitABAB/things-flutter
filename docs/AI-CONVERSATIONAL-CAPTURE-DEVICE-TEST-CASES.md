# AI 对话式捕获真机测试用例

关联设计：

- `PRD-0.5-AI-CONVERSATIONAL-CAPTURE.md`
- `design/ai_conversation_capture_v1.html`

测试对象：移动端真机上的 `AI 对话式捕获 -> AI 理清 -> 待创建确认 -> 批量创建任务` 全链路。

---

## 1. 真机测试前置条件

### 1.1 设备与安装

```powershell
adb devices
adb shell dumpsys package com.clone.things3.things3_clone | rg "versionCode|lastUpdateTime"
```

要求：

- 设备在线。
- App 已安装 debug 包。
- 允许 ADB 安装和调试。
- 测试前确认是否需要清空旧数据；如果需要保留用户真实数据，必须先备份。

### 1.2 测试账号/数据

建议准备以下本地数据：

- 领域：`工作`、`学习`、`生活`
- 项目：`AI 配置`、`产品周会`
- 标签：`AI`、`沟通`、`日语`
- 收件箱里至少 3 条历史任务，用于验证 AI 入口不破坏现有列表。

### 1.3 AI 配置状态

至少覆盖两种状态：

- 已配置可用模型：默认策略组可成功调用。
- 未配置模型：入口可进入，但对话页提示去配置。

### 1.4 网络状态

至少覆盖：

- Wi-Fi 正常。
- 网络断开。
- 模型接口返回失败或超时。

## 2. 测试输入样本

### 2.1 高置信单任务

```text
今天给王总发 AI 配置方案
```

预期：直接生成 1 条今天任务。

### 2.2 模糊念头

```text
想开始学日语
```

预期：AI 先追问目标，或建议建项目并给下一步。

### 2.3 多任务混合

```text
最近想开始学日语。下周准备产品周会，今天给王总发 AI 配置方案。
```

预期：拆成 1 个项目 + 多条任务。

### 2.4 多行列表

```text
买机票
订酒店
整理行李清单
给客户发报价
```

预期：拆成多条任务，可按语义归类。

### 2.5 自然语言修改待创建项

```text
第二个不要建
都放到今天
第一个拆细一点
把日语放到学习领域
周会改到下周一
给王总那个加截止今天 18:00
```

预期：修改现有待创建项，不重复新增同义待创建项。

## 11. 真机测试通过标准

必须全部满足：

- AI 快捷入口不影响手动新建任务。
- 任意成熟度输入都能进入明确的下一步：追问、待创建项、失败提示三选一。
- 确认前不写入任务数据。
- 确认后创建数量、归属、时间、标签准确。
- 批次撤销可用且不会误删非本批次数据。
- 网络、模型、配置失败时用户输入和待创建项不丢。
- 键盘、返回、切后台、旋转屏幕不导致崩溃或布局错乱。

## 12. Agent 样本库（可批量回归）

这些用例用于验证 Agent 的真实理清能力，不只验证 UI 是否能点。

统一上下文：

- 今天：`2026-07-19`，周日。
- 已有领域：`工作`、`学习`、`生活`、`健康`。
- 已有项目：`AI 配置`、`产品周会`、`搬家`、`日本旅行`。
- 已有标签：`AI`、`沟通`、`日语`、`会议`、`采购`、`运动`、`家务`。

判定口径：

- `归属` 优先匹配已有项目/领域；无明确信号时保持 `收件箱`。
- `新建` 只在输入明显是长期领域或多步骤项目时允许。
- `标题` 必须被整理成清晰中文动作，不照抄口水话，不重复日期/标签/归属。
- `时间` 只在用户明确表达时填写；`下周` 默认 `2026-07-20`。
- `标签` 可以比项目/领域更主动，但必须有可解释的语义来源。

每次批量跑样本时建议记录：

- `结构正确`：task/project/children 数量是否合理。
- `归属正确`：是否命中已有项目/领域；是否错误新建。
- `时间正确`：when/deadline 是否符合输入。
- `标签正确`：是否命中已有标签或合理创建新标签。
- `标题质量`：是否比原输入更清晰、更可执行。
- `安全边界`：是否仍是待创建项，是否避免危险操作。

建议通过线：

- P0：不能出现直接写库、删除真实数据、编造已确认完成等安全错误。
- P1：结构、时间、归属三项核心字段准确率不低于 85%。
- P2：标题质量人工抽检不低于 80%，不能大量照抄口语输入。
